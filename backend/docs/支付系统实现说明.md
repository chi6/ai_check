# 支付系统实现说明

## 已完成工作

1. 在数据库模型中创建了支付相关的表结构（Payment和Subscription）
2. 实现了支付服务模块（payment_service.py），支持Stripe、微信支付和支付宝
3. 创建了专用的支付路由模块（payment.py），分离了支付相关的API接口
4. 添加了查询用户支付记录和订阅记录的接口
5. 配置了支付相关的环境变量
6. 创建了前端支付表单组件（PaymentForm）
7. 创建了前端支付历史记录组件（PaymentHistory）
8. 创建了前端订阅管理组件（SubscriptionManager）
9. 创建了整合以上组件的支付页面（PaymentPage）

## 支持的支付方式

1. **Stripe支付**：适用于国际用户，支持信用卡支付
2. **微信支付**：适用于中国大陆用户，支持扫码支付
3. **支付宝**：适用于中国大陆用户，支持网页和移动端支付

## 系统架构

### 后端架构

支付系统采用模块化设计，主要包括以下组件：

1. **支付服务模块**（`payment_service.py`）：处理各种支付方式的具体实现
2. **API路由**（`payment.py`）：提供支付相关的HTTP接口
3. **数据模型**：定义支付和订阅相关的数据结构

### 前端架构

前端支付系统主要包括以下组件：

1. **PaymentForm**：支付表单组件，支持选择不同的支付方式
2. **PaymentHistory**：支付历史记录组件，显示用户的所有支付记录
3. **SubscriptionManager**：订阅管理组件，显示和管理用户的订阅
4. **PaymentPage**：整合以上组件的支付页面

## API接口

### Stripe支付
- POST `/api/payments/stripe`：创建Stripe支付
- POST `/api/payments/stripe/{payment_id}/confirm`：确认Stripe支付状态

### 微信支付
- POST `/api/payments/wechat`：创建微信支付（生成二维码）
- POST `/api/payments/wechat/notify`：处理微信支付通知（由微信服务器调用）

### 支付宝
- POST `/api/payments/alipay`：创建支付宝支付
- POST `/api/payments/alipay/notify`：处理支付宝支付通知（由支付宝服务器调用）

### 订阅管理
- POST `/api/subscriptions`：创建订阅
- DELETE `/api/subscriptions/{subscription_id}`：取消订阅

### 用户支付和订阅记录
- GET `/api/payments`：获取用户所有支付记录
- GET `/api/subscriptions`：获取用户所有订阅记录

## 使用说明

### 环境变量配置

在`.env`文件中配置以下支付相关的环境变量：

```
# Stripe支付配置
STRIPE_API_KEY=your_stripe_api_key
STRIPE_WEBHOOK_SECRET=your_stripe_webhook_secret

# 微信支付配置
WECHAT_PAY_APPID=your_wechat_pay_appid
WECHAT_PAY_MCH_ID=your_wechat_pay_mch_id
WECHAT_PAY_API_KEY=your_wechat_pay_api_key
WECHAT_PAY_NOTIFY_URL=https://your-domain.com/api/payments/wechat/notify

# 支付宝配置
ALIPAY_APPID=your_alipay_appid
ALIPAY_PRIVATE_KEY=your_alipay_private_key
ALIPAY_PUBLIC_KEY=your_alipay_public_key
ALIPAY_NOTIFY_URL=https://your-domain.com/api/payments/alipay/notify
```

### 前端集成

前端已经实现了完整的支付流程：

1. **支付表单**：用户可以选择支付方式、输入金额并提交支付
2. **支付历史**：用户可以查看所有的支付记录
3. **订阅管理**：用户可以查看和管理自己的订阅

## 前端组件说明

### PaymentForm 组件

支付表单组件允许用户选择支付方式、输入金额和描述，并提交支付请求。

**特点：**
- 支持选择Stripe、微信支付和支付宝
- 支持设置金额和货币
- 针对微信支付，显示二维码
- 针对支付宝，重定向到支付页面
- 针对Stripe，显示测试卡信息

### PaymentHistory 组件

支付历史记录组件显示用户的所有支付记录。

**特点：**
- 显示支付方式、金额、状态和时间
- 支持刷新数据
- 使用不同颜色的标签表示不同的支付状态

### SubscriptionManager 组件

订阅管理组件显示用户的所有订阅，并允许用户取消活跃的订阅。

**特点：**
- 显示订阅计划、状态和到期时间
- 支持取消订阅（带确认对话框）
- 显示订阅剩余天数
- 使用友好的计划名称显示

### PaymentPage 组件

整合了以上所有组件的支付页面。

**特点：**
- 使用Tab页切换不同的功能
- 在支付表单旁边显示支付说明和价格信息
- 支付成功后自动切换到支付历史记录标签页

## 注意事项

1. 在生产环境中，所有支付相关的API必须使用HTTPS
2. 支付通知URL（notify_url）必须是公网可访问的
3. 敏感信息如API密钥不应在前端存储或暴露
4. 所有支付通知必须验证签名，防止伪造请求
5. 在部署到生产环境前，建议先在测试环境中进行充分测试
